# Held-out skills: where they come from

This page records every source checked for the held-out set of real skills, what was found when each was opened on 2026-11-20, and how the set is built. The set exists so the tool can be measured on skills and labels that we did not write and did not tune against.

Counts below are each source's own claims unless it says "checked". Nothing here was executed. No skill content is committed: the repository holds only `tests/heldout/manifest.json` (where each skill is, a hash of it, and how it was labelled).

## Rules

- **Hold-out.** Nothing in the checks, profiles or prompts may be tuned on these skills. If a miss leads to a fix, that skill moves to the development set (`tests/fixtures/benchmark/`) and a reserve skill takes its place.
- **Labels are not ours.** Malicious means a published dataset says so and a second source or a read of the payload backs it. Benign means a reputable public repository. A skill that cannot be called goes in `ambiguous`, which is reported apart and left out of precision and recall.
- **Safe handling.** `scripts/fetch_heldout.py` reads skills out of a pinned shallow fetch without checking anything out, refuses symlinks, submodules, special files and unsafe paths, writes files without execute bits, verifies a SHA-256 of each skill against the manifest, and keeps everything in `~/.cache/skillsentry-heldout/`, outside the repository. A cache inside the repository is refused. Malicious skills are scanned statically only and are never run or sandboxed.
- **Privacy.** All sources are public.

### What this means for the malicious labels

- Real, human-confirmed, wild malicious skills are scarce and clustered. Most "malicious" rows are **constructed** (a payload injected into a real skill). The manifest records `provenance` and `evidence_type` for every skill so results can be split into wild and constructed.
- The datasets' own attack categories are coarse and sometimes arbitrary. Hidden text, reverse shell and "do not tell the user" skills are not categories there, so these classes were found by pattern in the skills the datasets already label malicious. The pattern only picks which already-labelled skill to include; it never changes a label.
- A skill whose label could not be backed (one dataset only, no payload found, not study-confirmed) was left out rather than guessed.
- "Social engineering" and "typosquat" are thin: the datasets label few skills that way, so those classes have fewer entries than the others.

Benign labels rest on the repository's reputation and licence. They are not guaranteed clean. Each is read through for anything dangerous before the set is frozen (see the manifest's `label_basis`), and a benign skill that turns out to be harmful would move to `ambiguous`.

## The set

`tests/heldout/manifest.json` has a `sources` table (URL, pinned commit, licence), an `entries` list (the test set) and a `reserve` list (about 40 spare skills used only to replace one that moves to the development set). Each entry carries the source, the path, the SHA-256 of the skill, licence, label, label sources and basis, and a category. Malicious entries also carry the attack class, provenance and the datasets' own categories.

Benign categories: document and office, creative and design, developer workflow, cloud and DevOps, data science, MCP and agent builders, browser automation, API integrations, security education, finance, writing and research, multilingual, large reference files, shell-heavy installers. A repository contributes at most one skill per category, and ordinary repositories contribute only one skill.

## Fetching

```
python scripts/fetch_heldout.py fetch          # download and verify the test set
python scripts/fetch_heldout.py fetch --set reserve
python scripts/fetch_heldout.py verify         # re-check hashes, no network
```

Use `python -I` and never open a fetched folder in an editor or tool that runs project code. Treat every file as untrusted text.
