# Changelog

All notable changes to **SkillSentry** are documented in this file.
Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [SemVer](https://semver.org/).

---

## Policy

- Every change a user or operator can notice gets an entry under `[Unreleased]`, in the same pull request.
- Entries are grouped as Added, Changed, Deprecated, Removed, Fixed, or Security.
- A release moves the `[Unreleased]` entries under a new version heading with its date, and then `[Unreleased]` is empty again.
- Old entries keep the names they had at the time. Do not rewrite history.

## [Unreleased]

### Security
- Package installs from a bare IP address are HIGH: `npm`, `pip`, `yarn`, `pnpm`, `cargo`, `go` and similar told to install from, or to use as a registry, a bare IP address, in a script or a fenced block. A registry that is named but not a standard one is MEDIUM. The anchor type is `untrusted-install`.
- The server is harder to misuse. (1) A folder the server cannot read, such as permission denied, now gives `422 path_unreadable` instead of a bare 500, and any other unhandled error returns the usual JSON error (`500 internal_error`, with the detail in the server log only). (2) With no `allowed_scan_roots` configured, `serve` now scans only the folder it was started in and prints it; before, any readable folder could be scanned. Set `allowed_scan_roots` to widen it. The official container is unchanged (any readable folder until roots are set). (3) New opt-in bearer token (`serve --token` or `SKILLSENTRY_TOKEN`, never printed or logged). When set, every API route except `/health` and `/meta`, and the WebSocket, needs `Authorization: Bearer <token>`, or the `bearer.<token>` WebSocket subprotocol; the comparison is constant-time, and a missing or wrong token gets `401 unauthorized`. `serve` now refuses a non-loopback `--host` without a token (exit 2); the official container, which binds `0.0.0.0` by design, still starts without one. 
- Hash-pinned installs are complete. The server image builds the project wheel in its own stage and installs it by hash with `--no-deps`, so the runtime image has no build backend (its lock now holds only the project's dependencies and `pip`), and the release SBOM tool installs from a hash-locked file (`requirements-sbom.txt`). `scripts/lock.sh` regenerates every lock. The decision for each OpenSSF Scorecard check is recorded in `docs/security/scorecard.md`, and `SECURITY.md` links the private reporting form.

### Changed
- A file the scan could not read for a reason about the scan (the text budget, the package size, an unsupported file type) is a coverage gap (finding type `coverage-gap`), not evidence of a threat. Before, a skill too big for the text budget got one HIGH finding per unread file, and HIGH from a non-model stage counted as strong evidence, so it came out MALICIOUS. It is now UNSCANNED with the reason. A compiled program is still `opaque-content` and still HIGH.
- The pattern anchors read their context. A pattern that is ordinary in documentation, in a fixed command or at a host the skill names is lowered to LOW, with the reason in the message; the same pattern in a script, with a bare-IP or tunnel destination, a credential read, hidden characters or lookalike text keeps its severity. Nothing is raised or removed. Measured on a new tuning set of real skills (`tests/devreal/manifest.json`, 151 benign and 39 malicious, disjoint from the held-out set): false alarms on scanned benign skills fall from 14.2% to 2.4% and recall from 92.1% to 100% (in-sample). The 83-skill development result is unchanged. See `docs/operations/devreal-set.md` and `docs/security/evasion-limits.md`.
- `rm -rf` is flagged for the root, the home folder or everything here, not for a named folder such as `/tmp/build`. The injection phrase also matches "preceding", "earlier" and "former" instructions.
- Big skills are read in order of risk and no longer end up `UNSCANNED` only because their reference text is long. The model now reads `SKILL.md` first, then ranges the static checks flagged, scripts and config files, instruction text, and last reference, asset and example text. Reference text beyond the call budget is a new coverage state, *static-only*: the static checks read it, the model did not. It is reported (a `semantic-static-only` check with `model_read_share`, `static_only_share` and the ranges), `coverage` falls by the share the model did not read, and a `SAFE` result says so. `UNSCANNED` still applies when `SKILL.md`, a script or config file, instruction text or a flagged range was not read by the model, or when a model call failed, was throttled, ran out of quota or timed out. The limit this leaves (an instruction-only attack in a long reference file) is documented in `docs/security/evasion-limits.md` and measured by a labelled known miss in the development benchmark, which also gains four synthetic big skills (`tests/fixtures/benchmark/big_skills.py`). Small files are packed into one request up to the profile's input size, so `SKILL.md` and several small scripts take one call. Text the model must read gets as many calls as it needs, up to four times the profile's call budget; the profile's budget applies to optional reading (reference text). A skill whose required reading does not fit even then, and a run that stops on a daily quota or rate limit, is still `UNSCANNED` with the reason. A bare `entry_point: <name>` that names an installed command, not a file in the package, is now a note instead of an INVALID SKILL error; paths, suffixed names and an interpreter's missing script are still rejected. The verdict cache key is bumped, so earlier results are rescanned.
- Rate-limit pacing no longer stalls. A call was admitted on the character estimate of its prompt, which is well above what a provider counts, so under a tokens-a-minute limit (the Groq preset's 6,000) about every third skill waited close to a minute for calls that took a second. The estimate is now corrected by how the provider's own count compared with it on earlier calls, a reply is reserved at what replies have cost (not the reply limit), the provider's `usage` replaces the estimate after each call, and a failed request gives its tokens back. A real overshoot is still absorbed: the provider's 429 and `Retry-After` are honoured. The Gemini client reconciles with the provider's token count too.
- A retry after a refused reply changes the request. It carries a reminder of why the reply was refused and to answer with one JSON object, and no further retry is made when the same refused reply comes back byte for byte. Before, a retry repeated the identical request, returned the identical reply at temperature 0, and spent quota. Applies to the OpenAI-compatible, local and Gemini clients.
- A model with a known smaller window gets it. `allam-2-7b` has a 4,096-token window, not its class's 8,192, so its requests are sized for 4,096. The ids `gpt-oss-20b`, `gpt-oss-120b`, `qwen3.8-27b` and `qwen/qwen3-32b` resolve to `reasoning`, and `llama-3.1-8b-instant` to `small`, with tests.
- The benchmark lists the skills on which a model's reply failed the schema, and counts retries (a retry is told by its reminder, so it is not counted as a first attempt).
- A line longer than a chunk is split, not left as a gap. The semantic stage used to record a line longer than the profile's chunk (3,000 characters for `tiny`) as unread, which made a benign skill with one long unwrapped paragraph UNSCANNED. The line is now split at whitespace into pieces that keep its line number (a hard split only when it has no whitespace), so every character is read and nothing is cut. Found by the precision benchmark: `b15-long-guide-near-limit` was UNSCANNED on both local models and is now SAFE.
- Free-tier rate limits and quota are handled. The OpenAI-compatible client (and the Gemini client, when limits are set) paces its requests to the provider's requests a minute, tokens a minute and requests a day, with one limiter shared per provider and model. The `groq`, `nim` and `openrouter` presets have starting limits, and `[model.provider]` takes `requests_per_minute`, `tokens_per_minute` and `requests_per_day` (`0` turns one off). A 429 uses `Retry-After`, or a capped doubling back-off with jitter; tokens come from the provider's `usage` figures, with a 3.2 characters-per-token estimate before a call. A daily quota ends the run's use of the model with one message: the skills not read are `UNSCANNED`, never `SAFE`, the message says how many skills the model read and how many it did not, and the exit code is `4` (it was defined but never returned before). A wait is never slept past `--max-time`; the stage is degraded with a note instead. `doctor` shows the limits in use.
- The semantic stage fits its requests to the model. Chunk size, calls per skill, findings listed per call, the reply schema, worked examples and retries now come from the model's profile instead of one fixed shape, for every backend: the OpenAI-compatible client and the local and cloud clients (which resolve a profile from their model id; for a local model the window and reply limit are the ones the server runs with). The input of a call is bounded by the real context window (the window, minus the reply, minus the fixed part of the prompt). Nothing is silently cut: a line too long for a chunk is a gap, calls beyond the profile's budget are gaps, findings that do not fit the list are counted and the model is told, and a window too small for any chunk makes the stage degraded with the reason. `tiny` and `small` models get a shorter reply schema and two worked examples. The profile, the provider and model id, and a hash of the prompts and schemas are part of the cache identity, so verdicts cached before this change are scanned again. Measured on the 14-skill corpus with `gemma3:1b` and `qwen2.5-coder:1.5b` (native path): every verdict, risk score and exit code is unchanged, and the semantic stage takes 39% and 18% less time. A model with no profile keeps the old fixed shape. Corrected classes: `phi-3-mini` and `phi-4-mini` are `tiny`, `mistral-small` is `mid`, and a mixture of experts such as `mixtral-8x7b` counts all its parameters (`large`).
- A refused skill returns at once. A package that is malformed (a HIGH frontmatter, entrypoint, symlink, encoding or reserved-name problem) or that holds content nothing can read (an executable, a file near the size cap, an unread script) ends as `INVALID SKILL` or `UNSCANNED` whatever a model says, so the model and the sandbox are no longer run for it. Before, each such skill still spent 4 to 20 s in the semantic stage with a small local model (and the full time with a large one). The static findings are kept, the status and exit code (`5` for INVALID) are unchanged, a note (`analysis-skipped`) says what was skipped, and `coverage` shows that the analysis did not run. A refused package that the static checks already found a threat in (MEDIUM or worse) still gets the full analysis, and a package with only a MEDIUM gap (an unknown binary type) is analysed as before. One status change: a skill with a declared entrypoint that does not exist, or is empty, used to be `UNSCANNED` (exit 1) because the sandbox stage failed; it is `INVALID SKILL` (exit 5) like the other malformed skills.
- A model request that times out, or whose reply is cut at the output limit, is no longer retried. The retry repeated the cost and the result: at temperature 0 a reply cut at `num_predict` was cut at the same place on 4 of 4 repeats, and a timed-out request is as slow the second time. With three chunks, two attempts and a 180 s timeout the worst case for one skill was 1080 s, which is the range of a 918 s scan in an outside review; it is now 540 s, and `--max-time` ends the scan first. Measured with a real model and a model server that never answers, the semantic stage took half as long with the same verdicts. A malformed reply and a server error are still retried once. Applies to the local and the cloud client (`ModelTimeout` and `ModelTruncated` are new subclasses of `ModelUnavailable`).
- `confidence` now means certainty in the verdict. Before, it was the share of the scoring weights that had a signal, so it was `0.44` for almost every scan whatever the verdict. Now a canary or evasion override is `1.00`; a MALICIOUS verdict backed by a deterministic finding is `0.85`, or `0.95` when the model agrees; a SUSPICIOUS verdict is `0.65` with independent evidence (`0.75` with the model), `0.40` when only the model flags it and `0.30` when only a failed check caused it; a SAFE verdict is `0.50 + 0.45 x coverage`, times `0.6` when the model flagged something nothing else supported; a failed check caps anything below MALICIOUS at `0.50`. The key and its 0 to 1 range are unchanged. The verdict JSON gains an optional `coverage`: the share of the checks that apply to the skill that ran (a check that does not apply, such as vision with no images, is not counted). It is also in SARIF run properties and the Markdown report; STIX still derives its indicator confidence from `confidence`. Verdicts cached under the old scoring are not reused (the engine version fingerprint changed). A lone typosquat now scores 40, not 30, so it no longer sits exactly on the SAFE boundary (a score below `safe_max` is SAFE, so 30 was the first SUSPICIOUS value); the headroom follows custom `tiers`. The tier boundaries are documented in the guide, the CLI reference and the API reference.
- An `INVALID SKILL` result has its own exit code, `5`, instead of sharing `1` with a MALICIOUS verdict. Before, a skill with a missing `description:` exited 1 under every `--fail-on`, which a pipeline could not tell from malware. Now `5` means the skill is malformed (bad frontmatter or entrypoint, a symlink, a non-UTF-8 `SKILL.md`, a reserved file name, or a package over 64 MiB, which used to exit 3), `--fail-on` never changes it, and it is never counted as MALICIOUS. In a run of several skills the most serious result wins: `3` (an operational failure), then `1` (a verdict at or above the gate), then `5`, then `0`. A pipeline that treated any non-zero code as "do not install" still blocks; one that tested `== 1` must also handle `5`. The JSON verdict of a malformed skill is unchanged (it still carries the stored tier); read the exit code or the text output for the INVALID status. The hint now names the real cause: frontmatter, entrypoint, symlink (remove it), SKILL.md encoding (save as UTF-8), reserved file name, or package size, where every case used to say "Fix the SKILL.md frontmatter". The finding for a symlink or a reserved name now points at that file instead of `SKILL.md:1`. A file system error while reading a skill (permissions) is no longer labelled `invalid_skill`; it is `unreadable_skill` and still exits 3.
- Content the scan cannot read is now flagged by what it is, and a package that is too large is refused up front. Before, a file with an image name that was not an image (random bytes, a program) could pass as SAFE, and a font or icon that was fine failed the gate. Now: a compiled program (ELF, Windows PE, Mach-O), under any file name, and any file of 48 MiB or more are HIGH `opaque-content` findings; an unread script stays HIGH; any other unreadable file (a dataset, archive, unknown binary) and an image-named file that is not an image are MEDIUM; and a small image, font or icon (up to 5 MiB) whose header matches its file name is only a NOTE and no longer degrades the scan. Programs and media are recognised by their first bytes only; nothing is decoded or run. A package over 64 MiB now fails before any file is read or any model is called, with a message that says what to remove (the hint also stops pointing at `doctor`). The finding type is `opaque-content`; a clean-looking skill with a hidden binary can no longer be SAFE.
- A scan now has a hard wall-clock cap. Before, `--timeout` bounded only the sandbox and the semantic stage ignored its timeout, so one scan could run for 15 minutes on a slow local model. The new `scan --max-time` (config `[scan] max_time_s`, default 300 s, 5 to 86400) caps one skill: a model call that overruns is abandoned, images and chunks not yet reached are recorded as gaps, the sandbox gets only the time that is left, and the stage is reported as degraded with a `scan-time-limit` note while the findings from finished stages are kept. A degraded result is never SAFE and is not cached. `scan --timings` prints per-stage durations to stderr; every stage also records `durationMs` in its telemetry and the stream's completed event carries `stageDurationsMs`. `ScanOptions` gains an optional `max_time_s` in the API schema. The verdict JSON is unchanged. An abandoned model request ends on its own client timeout (`[model] request_timeout_s`); it cannot be killed.
- A skill that has scripts but no `entrypoint:` no longer fails the gate. Before, the sandbox stage was marked failed, so the result was `UNSCANNED` with exit code 1, and a small model's claim of deception could add a spurious finding. Now the scripts are skipped (a command is still never guessed), the verdict comes from the static and model stages, the report has a `sandbox-no-entrypoint` note and the command prints a warning on stderr. The new `scan --strict-sandbox` flag (also the `strict_sandbox` scan option in the API schema) restores the old result: `UNSCANNED`, exit 1. A declared entrypoint that is invalid still fails, and a model-only deception claim with no other evidence still cannot raise the verdict. A strict scan is not cached.
- The dashboard is built with React 19 and TypeScript 7 (was React 18 and TypeScript 5.9). `react`, `react-dom`, `@types/react` and `@types/react-dom` moved together and stay pinned to exact versions. A small `ui/src/css.d.ts` declares stylesheet imports, which TypeScript 7 requires. No view, API or behaviour changed, and the build and tests needed no other source changes. Dependabot may now propose React and TypeScript major updates again.
- Dashboard views handle a failed load, a pending load and an empty result as different cases. A failed request shows a short message that says what to do (start the server when it cannot be reached, retry on a server error, a hint when the item was not found) with a **Try again** button, and a retry shows the loading state instead of the old error. The Cache view says when the cache is empty and disables **Clear cache**, the Skill view keeps its back link while loading, and the Triage empty state also names the CLI command. Loading uses `role="status"` with `aria-busy`, errors use `role="alert"` and carry a border and a warning sign as well as colour. The server API is unchanged.
- The Markdown report is easier to scan. A multi-skill run (and any no-path run, even for one skill or none) opens with a summary: a counts table of scanned, failed and skipped, the verdict totals, then a table of skills with the most serious verdict first (MALICIOUS, SUSPICIOUS, UNSCANNED, INVALID SKILL, SAFE), highest risk first within a verdict. Skills that failed to scan are named under a `Failed` heading, and discovery notes appear under `Notes`. The per-skill reports follow in the same order. A no-path scan with nothing to scan prints a summary that says so instead of nothing. For skills found by a no-path scan, each per-skill report also lists the agent, scope and install path. Findings, citations and verdicts are unchanged, and so are JSON, SARIF, exit codes and text output. The `summary.md` saved by `--save-report markdown` and `--report-dir` has the same layout.

### Added
- `scripts/benchmark_models.py --manifest` scores the held-out set of real skills. Headline recall uses payload-confirmed malicious skills only; skills a study labelled malicious without a payload are reported as their own group and never as false negatives. It reports Wilson 95% intervals on recall and on the false-alarm rate, splits by category, source, attack class and provenance, lists every miss by id, refuses the sandbox and an in-repo cache, writes no skill content or model quote, and records which version of the checks and profiles made each run. The manifest gains `label_quality` for every entry.
- A held-out set of real skills for measuring the tool on labels we did not write: `tests/heldout/manifest.json` lists about 310 skills (188 benign, 97 malicious, 24 ambiguous) plus a reserve, each with its source, pinned commit, hash, licence and label source, and no skill content. `scripts/fetch_heldout.py` downloads them into a cache outside the repository without running or checking out anything, and refuses symlinks, submodules and unsafe paths. The sources and how they were checked are in `docs/operations/heldout-sources.md`.
- `docs/user/models.md`, a guide to choosing and running a model: how to pick a provider and a model class, the configuration for a local server, any OpenAI-compatible server, OpenRouter, NVIDIA NIM, Groq and Gemini (keys only from environment variables), a free-tier limits table stamped as third-party reports to verify, the privacy rule, the profile table, how to run the roster and benchmark scripts, and the local-tier results, including that model-only evidence cannot raise a skill the checks leave clean and which two skills are still missed.
- Two gaps in the deterministic checks, found by the benchmark. A `privilege-escalation` check (HIGH) for a passwordless sudo grant (`NOPASSWD:`), a write to `/etc/sudoers` or `sudoers.d`, a setuid bit (`chmod u+s`, `chmod 4755`) and adding an account to `sudo`, `wheel` or `root`; and `credential-store` checks for a browser's cookie store (HIGH) and a browser profile folder (`.mozilla`, Chrome, Chromium, Brave, Edge; MEDIUM). Prose that only mentions these does not match; the 33 benign benchmark skills and the benign fixtures are unchanged.
- A test that a hostile model cannot move any benign skill, and cannot flag a skill the checks leave clean, even when it claims critical evidence with a real quote.
- A precision benchmark for models. `scripts/benchmark_models.py` scans a labelled set with each model (`--model provider=model`; a provider without its key in the environment is skipped and nothing is sent to it, and a local model over 4 GB is refused unless `--allow-large`) and writes `matrix.md`, `summary.json` and `rows.jsonl` under `docs/operations/model-matrix/<date>/`: the confusion matrix and precision, recall and F1 for SUSPICIOUS-or-worse, false positives and negatives by name, what the model changed against the deterministic checks alone and whether it was right, replies valid on the first attempt, truncation, timeouts, 429s, the share of quoted evidence that exists in the skill, tokens in and out, time, and the flip rate across repeats. It is resumable: rows are appended as they are produced, and a scan a quota cut short is not recorded as a result. The set (`tests/fixtures/benchmark/`) adds 30 benign and 20 malicious skills, including cases only a model can judge, to the 14-skill corpus and the evasion fixtures. See `docs/operations/model-benchmark.md`.
- Model profiles (`core/models/profiles.py`): five capability classes (`tiny`, `small`, `mid`, `large`, `reasoning`), each with a context window, a reply limit, a chunk size and count, a retry count and whether the prompt carries examples. The class is chosen from the model id by pattern (parameter count in the name, and known reasoning and hosted model names), an unknown model gets `small`, and `[model.profile]` overrides the class or any one value. The OpenAI-compatible client takes its reply limit and structured-output start from the profile (an explicit `max_tokens` still wins), and the profile name is part of the cache identity. `[model.provider] max_tokens` now defaults to the profile's value instead of 2048. The semantic stage keeps its present fixed limits for now, so scans with the local and cloud backends are unchanged.
- `scripts/list_free_models.py` writes a dated roster of what OpenRouter, NVIDIA NIM, Groq and the local server offer, with a profile class per model and, optionally, a one-token probe per model (status, time, and the rate-limit headers the provider returns). Keys come only from the environment, a provider without its key is skipped and nothing is sent to it, and a probe sends only a fixed sentence. See `docs/operations/model-roster.md`.
- `doctor` checks the configured OpenAI-compatible provider instead of Ollama: which server and model, the profile it resolved, a privacy line for a remote provider, whether the key variable is set (never the key; with no key no request is sent), and whether the server lists the model. `doctor --backend NAME` checks another backend, and `setup` no longer offers an Ollama download when a provider is configured.
- One client for any OpenAI-compatible model server. `[model] backend` accepts `openrouter`, `nim`, `groq` (presets that fill in the address and the key variable) and `openai` (any server, with `[model.provider] base_url`), and `--backend` takes the same names. It reaches OpenRouter, NVIDIA NIM, Groq, Cerebras, Mistral, GitHub Models, LM Studio, vLLM, llama.cpp and Ollama's `/v1` endpoint. Structured output starts at `json_schema` and steps down to `json_object` and then to plain prompting when the server answers 400 or 422 to `response_format`, remembering what worked; every reply is still parsed and checked against the schema. `<think>` blocks are removed before the JSON is read. HTTP 429 is honoured once with `Retry-After`; a timeout and a reply cut at `max_tokens` fail at once. Keys come only from environment variables (`OPENROUTER_API_KEY`, `NVIDIA_API_KEY`, `GROQ_API_KEY`, or the variable named by `api_key_env`), are read when a request is made, and appear in no file, log, error message, report, JSON output or cache row; a configuration that puts a key where a variable name belongs is refused, and a configuration error no longer repeats the value that was wrong. A remote provider is never chosen by `auto`, and the banner and report name it. A server on this machine needs no key and is reported as local. The older `ollama_*` and `gemini_model` keys and the `local` and `cloud` backends are unchanged. `Backend` in the API gains `openai`, `openrouter`, `nim` and `groq`.
- Hidden characters are now found. A message can be written in characters that draw nothing: zero-width characters read as bits, Unicode tag characters, or variation selectors used as bytes. The real-model verification run found a skill carrying one that scanned `SAFE`. A run of eight or more invisible characters in a row is a `hidden-characters` finding (LOW in prose, MEDIUM in code, code blocks and command lines, HIGH from 64 up). The invisible characters of a line are decoded, and readable ASCII is a `hidden-text` finding (HIGH) that is also matched by the instruction, credential and shell rules, with the original file and line as the evidence. Ordinary uses are untouched: emoji sequences, Persian and Indic joiners, Arabic direction marks, a byte order mark and soft hyphens (tests use real examples, and a scan of this repository found nothing). The `bit-encoded-text` known gap is closed; `tag-characters`, `variation-selectors` and `invisible-run` cases were added, and the evasion docs list no known gaps. Encodings with three or more symbols, other bit widths, and payloads split over several lines are not decoded.
- `scripts/verify_corpus.py` builds a 14-skill verification corpus (benign with and without an entrypoint, exfiltration, `curl | bash`, obfuscated payload, two prompt injections, typosquat, time bomb, a 50 MB file, bad frontmatter, non-UTF-8, symlink) and scans it with the installed command, recording verdict, exit code, wall time and per-stage time. `docs/operations/verification-2.1.x.md` records a run with a real local model and a real Docker sandbox, with the raw rows, and the one miss it found (a payload in zero-width characters, now a documented known gap with an evasion case).
- The dashboard supports a server started with a token. On a `401` it shows an "Access token needed" page instead of failing: a wrong token is refused with a message and nothing is stored; the right one loads the dashboard. The token is kept in memory and `sessionStorage` for that tab only (never `localStorage`, never in a URL, never in the page), is sent as `Authorization: Bearer` on requests and as the `bearer.<token>` subprotocol on the scan WebSocket, and a **Sign out** button in the header forgets it. A token that stops working brings the prompt back. The WebSocket handshake now selects the plain subprotocol `skillsentry.v1`, which the dashboard offers next to the token; a browser rejects a handshake that selects none of the protocols it offered, and the token is never echoed back. Servers without a token behave as before: no prompt and no sign-out button.
- A cross-file check finds a download in one file that another file runs. Each script was ordinary alone (`urlretrieve(..., "/tmp/p.sh")` in one, `/tmp/p.sh` in another) and no pattern matched. The check collects the paths each script writes and runs, and reports a path that one file writes and a different file runs: `download-then-exec` (HIGH) when the write is a network download, and `write-then-exec` (HIGH) for a local write of something that looks like code. A local write of a config or data file that another script sources is not reported, because that pattern is normal. The evidence names both places: `file` and `line` are the run, `writerFile`, `writerLine` and `writerCode` the write. It reads shell, Python (syntax tree), Node and PowerShell, understands `curl` and `wget` options in their usual spellings (bundled short options such as `curl -sSLo FILE` and `wget -qO FILE`, attached values such as `-o/tmp/p.sh` and `--output=FILE`; `wget -o` is a log file), follows constants, f-strings and shell variables (also one set earlier on the same line, `D=/tmp/w; curl ... -o $D/z`), and counts a path as run only when it is the command, an interpreter's script, made executable or passed to an exec call, so a script that downloads data and another that only reads it stay SAFE. The `split-download-exec` evasion case is now caught (with shell and Node variants), and the evasion docs list one known gap; the remaining limits are paths built at run time and a file that downloads and runs its own download (left to the single-file patterns). The lookalike table moved to `core/anchors/confusables.py`.
- The deterministic checks now see through lookalike characters. Each line is matched as written and in a normalised form: NFKC folds full-width and mathematical letters, a short table maps Cyrillic and Greek letters that are visually identical to a Latin letter, and invisible characters (zero-width, bidirectional controls, soft hyphen) are dropped. Normalising only adds matches (the original line is tried too, and no pattern changed); a finding keeps the original file, line and text, and a hit that needed normalising says so. Python files are also parsed in the normalised form, and credential-flow checks run on it. A word that mixes Latin letters with lookalikes and reads as ASCII (`сurl`) is a new `mixed-script` finding: MEDIUM in code, scripts, code blocks and command lines, LOW in prose. Text in one alphabet (Russian, Greek, CJK, accented Latin) is not flagged and stays SAFE, with tests for that. The `homoglyph` evasion case is now caught, and `fullwidth-forms`, `invisible-chars` and `greek-in-script` cases were added; the documented known gaps drop from two to one (a download in one file, run in another).
- `export --format json` (and `GET /skills/{id}/export?format=json`) renders the verdict JSON, the same document `scan --format json` prints for one skill, so `scan` and `export` share `markdown`, `sarif` and `json`. No flag was removed.
- Documentation of what a verdict means and where it can be evaded: a "What a verdict means" section in the user guide, `docs/security/evasion-limits.md` (how a verdict is reached, the cases tested and the two known gaps, with reasons), a light-mode recipe for machines without Docker or Ollama (`[decision] backend = "none"` with `--no-sandbox`), a note that a console script's shebang is not relocatable (recreate the virtual environment or reinstall after moving it), and a table of which output option to use when (`scan --format/--output/--sarif-out/--report-dir/--save-report` and `export --format`).
- Evasion test fixtures in `tests/fixtures/evasion/` with expectations in `tests/expected_verdicts.json`: five obfuscations are caught (string concatenation, a split base64 payload, an indirect `getattr`/`__import__` call, an injection in a long table, and the plain baseline) and two are recorded as known gaps, as strict expected failures with a reason: a Cyrillic lookalike letter in a `curl \| bash` line, and a download in one file run by another. No pattern was changed or loosened. A known gap that starts being caught fails the suite until its entry and the docs are updated.
- The JSON verdict has an explicit `status`: `SAFE`, `SUSPICIOUS`, `MALICIOUS`, `UNSCANNED` or `INVALID SKILL`, the same value the text output shows. Before, a script reading JSON could not tell an invalid or unscanned skill from a verdict (an invalid skill carries a stored tier of SUSPICIOUS or MALICIOUS). `verdict` is unchanged. The verdict also gains `checks`: passing checks (`spec-valid`, `semantic-clean`, `anchors-clean`) are listed there instead of in `findings`, so `findings` holds only what needs attention. Evidence objects no longer carry a dozen `null` keys: only fields that have a value are written, and a finding without a type omits `type`. All of these fields were already optional in the schema, so schema-following readers are unaffected; a reader that indexed an evidence key without a default, or looked for `spec-valid` among the findings, must change. The dashboard is unchanged (it still lists the checks with the findings), and SARIF and Markdown no longer list passing checks as results. Results cached before this change are scanned again.

- `scan` with no path, in a text run on an interactive terminal, asks whether to save a report. `--save-report markdown|sarif|none` decides without asking, and `--no-prompt` skips the question. Reports are saved under `~/.skillsentry/reports/`. The question is never asked when the input or output is not a terminal.

### Security
- The local server refuses any request whose `Host` header is not loopback or its bind address, with `400 untrusted_host`. A WebSocket handshake with a foreign `Origin` is refused before it is accepted. This blocks DNS-rebinding access to scans and code excerpts.
- A cross-site page cannot start a scan, clear the cache, or read scan results over a WebSocket. A `POST`, `PUT`, `PATCH`, `DELETE` or WebSocket handshake whose `Origin` is not the server's own origin (same scheme, host and port as `Host`) or a dev origin such as `http://localhost:5173` is refused (`400 untrusted_host` for HTTP, close code 1008 for WebSocket), including an `Origin` of `null`. ### Changed
- **UNSCANNED status.** When a stage is degraded, the CLI and folder summary show `UNSCANNED` with the verdict and the reason, instead of presenting the SUSPICIOUS score as a normal result. The JSON verdict contract is unchanged, and exit codes still follow the verdict.
- **`--backend demo` is refused** for `scan` and `self-audit` unless `SKILLSENTRY_DEV=1` is set. Use `--demo-mode` for the canned store.
- The report and CLI badge no longer name a model.
- Local model client: configurable context size, prediction cap, seed and keep-alive. Health requires the configured model to be pulled, so a server without it no longer answers with another model. Cache identity uses `name@digest`.
- Legacy semantic analysis splits skills into line-aligned chunks within a call budget. Anything not analysed is reported as a coverage gap and sets the stage to degraded.
- Raster images sent to the model are capped at three per scan, downscaled to 768 px. The rest are reported as partial coverage.
- `--fail-on` defaults to `suspicious` for `scan` and `self-audit`.
- The default model is `gemma4:e4b-it-qat`, the build that was pulled and verified.
- The Laya decision backend is opt-in (`decision.backend = "legacy"` by default) until its calibration gates pass.
- The version is read from `skillsentry/core/version.py`.
- Documentation: `docs/07` matches `--help` (fail-on default, `init`, `serve`, `self-audit`, cache and export flags, environment variables). `docs/02`, `04` and `08` now state the 768 px vision cap, the three-image budget, the fail-closed model path and the cloud backend name.

### Fixed
- `cache list` shows the scan ID, skill, status and verdict; `cache stats` reports the database file size and the hit rate (it printed the hit rate as the size).
- A missing config file named by `SKILLSENTRY_CONFIG` is an error (exit 2), not a silent fallback to defaults; the CLI never shows a traceback for a bad config.
- An unreachable model server is named in the UNSCANNED reason.
- **Model evidence alone cannot make a verdict MALICIOUS.** A MALICIOUS tier needs a malicious override, or a non-model finding or signal of HIGH or above. Otherwise the verdict is capped at SUSPICIOUS and a NOTE says so. Model findings can still raise a verdict to SUSPICIOUS.
- **Model citations are verified.** A quote the model cites must appear in the skill; the reported line is the one that contains it. Unverifiable quotes are dropped and counted in a NOTE.
- **Ordinary network code is not a reverse shell.** A plain socket is MEDIUM. CRITICAL is reserved for reverse-shell primitives (`/dev/tcp`, `pty.spawn`, `os.dup2`). The DNS rule matches only commands, not the word "host" in prose.
- **Cache identity includes generation options** (context size and prediction limit). Changing them no longer serves a cached result.
- **CLI writes report an unwritable path** as an operational error (exit 3) instead of a traceback.
- **Unknown API paths return a JSON 404**, not the dashboard page.
- **Model probe** distinguishes an unreachable server from a missing model; `doctor` says which.
- **Model errors keep their own message** (HTTP status, truncated, empty, transport). Only malformed output is called "no schema-valid JSON".
- **Sandbox timeout message** states the configured limit and the elapsed time.
- **Docker clients are closed** (runner, engine, doctor, sandbox build, health probe).
- **Dashboard dev-server dependencies** upgraded (Vite 8); the audit reports no vulnerabilities.
- **Lower dependency bounds** raised to versions that install and pass the suite: typer 0.16, PyYAML 6.0.1.
- Python 3.13 added to the classifiers and the CI matrix; the suite passes on 3.11, 3.12, and 3.13.
- Sandbox base image pinned by digest; Pillow pinned.
- The test suite is portable to an installed package: source-checkout gates skip cleanly when run outside a checkout.

- **Stable verdicts.** The prompt fence nonce is derived from the excerpt, so an identical skill produces an identical model prompt. Model replies are bounded (at most 8 patterns, short evidence), so a reply no longer fails by running past the token cap depending on the run.
- **No silent skips.** A text file that is oversize, over the text budget, or unreadable is reported as a HIGH "text file not analysed" finding, which degrades the spec stage. Extensionless scripts at the root are read.
- **Symlinks and bad encodings are findings.** A symlink is hashed as a link and reported (HIGH), and the rest of the skill is still scanned. A non-UTF-8 `SKILL.md` is reported (HIGH) and analysed with replacement characters.
- **PowerShell download-and-run** (`Invoke-WebRequest | Invoke-Expression`, `iex (…DownloadString…)`) is detected as a HIGH `shell-exec` anchor.
- **Health** reports Ollama as `ok` when the configured model is pulled, using the same readiness check as the model layer.
- **Tests are isolated** from the user's cache and scan history: the test database is a temporary file.

- Cache identity now includes a fingerprint of the credential rules file, so editing the rules cannot serve cached verdicts from before the edit.
- Fusion applies the strongest malicious override floor, so an evasion probe reports 100 even when a Poisoned Well override is listed first.
- Parser: YAML aliases and nesting deeper than 10 levels are refused before expansion. Reserved device names and alternate data stream notation are reported and the file stays in analysis.
- Typosquat: a case-only variant of a known name, and Cyrillic or Greek homographs, are flagged.
- SVG: UTF-16 documents are decoded and scanned, the whole document is scanned rather than the first 20,000 characters, and external `<use>`, `data:` URIs, DTD entities, remote stylesheets and hidden text are detected.
- **Docker 29 sandbox execution**: removed `/proc` bind mounts and serve sanitised cgroup/mountinfo views through the shim; added `stat64`, `fstatat`, `statx`, and versioned glibc stat interception so `/.dockerenv` stays hidden from shell and coreutils probes; seed `/tmp/skillsentry` via exec on the tmpfs; use an anonymous canary-home volume; serialize all runners process-wide; and reset a RUNNING scan row when a post-history `ScanError` occurs.
